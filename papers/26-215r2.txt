1. Introduction
---------------

The module procedure PROCEDURE_NAME is new in Fortran 2028, and there
are a few typos in the description of the procedure.

Paper 26-215r1 (an earlier revision of this paper) was discussed and passed by
J3 on 2026-10-26, after which defects were found in the same subclause whose
resolution involves overlapping edits.  This paper supersedes prior revisions.

2. Updates in Revision 2
------------------------

The support for adding a procedure's binding-name into the contextual
output has shown some potential technical problems.  It was originally
added by subgroup because it was considered "free", but further
examples, and in fact original edits promoted by this paper, have
shown that not to be true.

One area of potential confusion is with procedures contained within a
routine that has a binding name.  For example:

SUBROUTINE S() BIND(C, NAME="S")
CONTAINS
    SUBROUTINE INNER()
        USE ISO_FORTRAN_ENV
        PRINT *, PROCEDURE_NAME(.TRUE.)
    END SUBROUTINE
END SUBROUTINE

Should it return S=S.INNER, or simply S.INNER?  We suggest that it
should be subprogram-name.internal-subprogram-name, but it is not
unlikely there could still be questions.

The more egregious issue is with deferred parameters and templates,
as shown below:

MODULE EXAMPLE2
    TEMPLATE TMPL{C}
        DEFERRED CHARACTER(*), PARAMETER :: C
    CONTAINS
        SUBROUTINE S() BIND(NAME=C)
            PRINT *, PROCEDURE_NAME(.TRUE.)
        END SUBROUTINE
    END TEMPLATE
END MODULE

In this case the value for "C" is only known at template instantiation time,
not at compile-time of the template. This implies the result of a PROCEDURE_NAME
invocation within a template *might* be a deferred constant, but only in this
corner case. In all other cases the result of a PROCEDURE_NAME invocation within
a template is constant at template declaration time (which was the intent).

With this all in mind subgroup recommends that we remove the output
of binding-name from the CONTEXT=.TRUE. return value.

This simplifies the edits requested in original 26-215
